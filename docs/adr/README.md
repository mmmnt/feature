# Architecture decision records

ADR-0001 to ADR-0021 live outside this repository and were never committed here. Publication of
these records outside the repository is deferred (founder, 2026-11-09: "put the ADRs in the repo,
we can worry about publication later").

- [ADR-0022](ADR-0022-uppercamel-rejection-ids.md): rejection ids may be UPPER_SNAKE or UpperCamel, kept verbatim and compared case-sensitively.
- [ADR-0023](ADR-0023-adapter-interface-v2.md): adapter interface v2: observation modes, the scenario clock, fault injection.
- [ADR-0024](ADR-0024-tier-bindings.md): tier bindings: one set of specs, an overlay config per environment.
- [ADR-0025](ADR-0025-given-written-order.md): a given's seed and execute lines run in written order, recorded in the IR as `given.order`.
- [ADR-0026](ADR-0026-local-vitest.md): the runner runs the project's own vitest, resolved from the root, and never fetches one; no vitest is VITEST_NOT_INSTALLED, exit 2.
- [ADR-0027](ADR-0027-not-matcher.md): the negation matcher `not <matcher>`: present and the operand fails; `not not`, `not absent`, bare `not any` and `not { … }` refused; an unresolvable reference operand is a violation.
- [ADR-0028](ADR-0028-model-adapter-judgment-file.md): the model adapter is a recorded judge: one JSON Lines file per namespace, seeds are answers the adapter writes, asks are lines the system writes; no network, no model, no faults.
- [ADR-0030](ADR-0030-f32-digest-matcher.md): the f32 digest matcher `f32 <dims> sha256 "<hex>"`: an array of exactly dims numbers, each exactly an f32, whose little-endian f32 bytes hash to the digest; absent, non-array, wrong length, a non-f32 value and a differing digest are violations; `not f32 …` refused.
- [ADR-0031](ADR-0031-local-gate.md): the local gate is the explicit `scripts/ci-local.sh`, and pre-push only checks its pass record (the push held its connection idle through the gate and silently did not land); one gate at a time by the host-wide `~/.flmnt/gate.lock` and a CPU check; jobs serial (side by side measured not identical); turbo's build cache kept and bounded; `--changed`/`--rebased` scoped checks.
- [ADR-0032](ADR-0032-pr-report-action.md): a pull request build report Action (`actions/pr-report`): one updating comment and a required check, an auditable chain of evidence from PR head to signed provenance and the transparency log, main re-attests with a merge-linking attestation, fork PRs reported by a trusted follow-up; every push to main is attested, a direct commit (no pull request) included, under `pr-merge/v2` with the pushed range listed (decision 15).
- [ADR-0033](ADR-0033-observes.md): a spec may declare `observes <service>, ...`; no line = every configured service; an unconfigured key is UNKNOWN_SERVICE_KEY and a used-but-undeclared one UNOBSERVED_SERVICE; observes narrows successes and errors only, a rejection and a query still prove zero effects on every configured service.
- [ADR-0034](ADR-0034-list-matchers.md): matchers inside a list: a list that holds a matcher is `{ matcher: "list", items }`, exact in length and order, and an object inside it is `{ matcher: "object", fields }`, exact in its keys; a list with no matcher stays a literal, so no existing IR changes; `absent` as an item or as a field of an object inside a list, and `not [ … ]` over a list that holds a matcher, are refused.
- [ADR-0035](ADR-0035-seed-transform.md): a consumer's spec host may transform the store adapters' seeds (`options.seedTransform: { host }`, the optional protocol method `transformSeed`, asked twice and compared as canonical JSON, count/order/type/identity kept); every seed, transformed or plain, is checked against its store's storable forms (SEED_VALUE_UNSTORABLE) before anything is written; Neo4j, Redis, Kurrent and DynamoDB in one release.
- [ADR-0036](ADR-0036-deliver-to-response.md): `deliver <Event> { … } to response` hands the event to the response adapter's optional `deliver()` (the stdio-jsonrpc response role sends the existing `deliver` with `service: "response"`); `response` is a reserved target, never a service; no IR or protocol change.
- [ADR-0037](ADR-0037-deliver-answer.md): what the response role answers to a delivery is the case's captured response (the last delivery to response that answered), so a delivery-only case can predict `response`; a service's answer is never kept; `deliver`'s protocol result widens to empty or the invoke result's shape; no IR change.
- [ADR-0038](ADR-0038-optional-field-lint.md): a predicted record or response block that leaves out an optional property of its schema is the lint error `OPTIONAL_UNSTATED` unless it is marked `partial` (written where `equals fixture` sits); `partial` is refused in data, inside values and beside a golden; the IR records `"partial": true`; the runtime's comparison is unchanged.
- [ADR-0039](ADR-0039-exact-nested-blocks.md): a nested value block is exact — an undeclared key of its object is a violation in `has`, `contains` and responses, inside `partial` blocks too; the top-level block stays partial (ADR-0038); `absent` stays allowed; the migration lint `NESTED_SCHEMA_OPEN` warns on a nested block whose schema is open; feat-runtime 0.10.0, breaking.
