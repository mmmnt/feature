# ADR-00NN (DRAFT): The stdio JSON-RPC adapter, the Feat Host Protocol and host sharing

Status: draft, awaiting the founder. Numbering is the project's to assign.
Inputs: founder rulings 2026-11-09 (Sift workspace entries 79123645, 473acc1d); ADR-0020 (peekCapture), ADR-0021 (settle), ADR-0012 (scenario clock), ADR-0011 (deliver, specType).
Governs: `adapters/stdio-jsonrpc` (`@mmmnt/feat-adapter-stdio-jsonrpc`), `schemas/feat-host-protocol.schema.json`, SPEC-RPC-001, SPEC-RPC-002.

## Context

A unit-tier instrument for a system written in another language (Sift's Rust host, FLMNT-ADR-006 section 4, SIFT-ADR-091) needs Feature's adapters to talk to a process. The first protocol and adapter were called "wire"; the word is too loose (it names no protocol and no transport) and is retired. At the integration tier the host only invokes and observation goes through product adapters; journeys never use this adapter.

Facts about the runner that constrain the design:

- `feat run` spawns `vitest run` (`packages/feat-runner/src/index.ts`). Vitest runs spec files in parallel workers and a file's tests in order. The harness builds the response adapter and every service adapter once per file (`packages/feat-runtime/src/harness.ts`).
- The harness resets every service adapter, then seeds, then opens capture windows, then invokes, delivers, awaits convergence (settle, then peek, then ceiling), then stops capture.
- A Rust host on a multi-thread tokio runtime can return from a handler while a task it spawned has not yet written. A fence that vouches at handler return would hide that write (ADR-0021 states this limit for in-process instruments).
- The scenario clock (ADR-0012) reaches only the handler adapter today; remote protocols need their own hook (grammar reference, `clock at`).

## Decision

1. **Names.** Adapter `@mmmnt/feat-adapter-stdio-jsonrpc`; protocol "the Feat Host Protocol"; schema `schemas/feat-host-protocol.schema.json` (`$id contracts/adrs/feat-host-protocol.schema.json`). The program on the other end is "the spec host".
2. **Transport.** JSON-RPC 2.0, one JSON object per line, host stdin for requests and stdout for responses; stderr is the host's log and is never parsed. One request outstanding at a time. Request `id` is an integer >= 1.
3. **Methods (13).** `setup`, `teardown`, `reset`, `setClock`, `invoke`, `seed`, `startCapture`, `peekCapture`, `stopCapture`, `settle`, `read`, `deliver`, `fault`. Params and results are CLOSED (`additionalProperties: false`) except values the protocol carries opaquely (invoke `input`, seed `values`, read `query`, deliver `payload`, capture `payload` and `metadata`).
   - Shapes mirror Feature's types: seed records are `SeedRecord` (`type`, `schemaName?`, `values`); capture results are `CapturedRecord[]` (`type`, `key?`, `payload`, `timestamp`, `metadata?`); `invoke` returns `CapturedResponse` (`status`, `body`, `headers?`, `metadata?`).
   - `startCapture {service, specType?}` carries the spec type (ADR-0011).
   - `reset {}` takes no parameters. It is idempotent and host-wide: it clears every port's state and capture window and every armed fault. It does not touch the clock.
   - `setClock {clock}` carries the scenario clock: an RFC 3339 date-time WITH a zone designator freezes it, `null` unfreezes it (the host's wall clock). The harness calls it on every case after the resets, response role first and then each service role in config order (`drafts/adapter-interface/DESIGN.md` section c); the null on a case without `clock at` stops one case's freeze reaching the next. The adapter refuses a clock without a zone designator (`INVALID_CLOCK`, in the adapter, before it reaches the host); a malformed clock that does reach the host is refused with -32602. The harness resets every service role before any seed (harness.ts, reset loop precedes the seed loop); the protocol relies on that order.
   - `setup {protocol, services, namespace}` (`protocol` is the integer const 2) and `teardown {services}` are ADDITIVE per role: they open or close the named ports and never touch another role's. A response-only role sends `services: []`. `namespace` is the runner namespace of the spec file (SPEC-RT-006, exactly `^s[0-9a-f]{12}$`, on the request and on the echo); every role of a file sends the same value, the host keeps the first and answers -32602 to a later role that sends another. The setup result is `{protocol, namespace}`: the host echoes the namespace it is running under. `reset` never changes the namespace; `teardown` forgets it when the last role leaves.
   - `peekCapture {service}` returns the records captured since `startCapture` without consuming them; repeatable; `stopCapture` returns the same records (plus any that arrived since) and closes the window.
   - `settle {service}` returns `{settled: boolean}`. The host answers `true` only when every task the scenario spawned (on any port) has finished and its effects are visible to `stopCapture`; a host that does not track its spawned tasks, or one whose task failed, answers `false`. The harness then keeps the convergence ceiling. A false answer is never an error.
   - `fault {service, kind, times?}` arms a logical fault for the current scenario. The host consumes it at the port named by `service` (the next `times` uses; every use until reset when `times` is omitted). `kind` is a name the host declares; an unknown kind is refused with -32602. `reset` disarms. The grammar that arms faults (`given fault`) is specified elsewhere; this ADR fixes only the method and its consumption rule.
   - `read` returns an array of records or `null`.
4. **Errors.** Standard JSON-RPC: -32700 parse error, -32600 invalid request, -32601 method not found, -32602 invalid params; implementation codes stay in -32000..-32099 (Sift uses -32002 for "not set up"). A response whose request id is unknown carries `id: null` and only -32700 or -32600. A host that cannot read a line well enough to find its id MUST answer with `id: null` rather than stay silent (a silent host is indistinguishable from a hung one and costs the client its full timeout).
5. **Validation, both directions.** The client validates every request before sending (an invalid request never reaches a host) and every answer on receipt, including the result against the closed shape for the method it sent (`#/definitions/results/<method>`). An answer that violates the schema is a protocol violation, not a data problem. The host validates every request line against the same schema.
6. **Schema dialect: draft-07.** Feature validates with Ajv's default class (draft-07; `corpus:validate --spec=draft7`; SPEC-RT-001). Ruled agreed. Draft 2020-12 needs the separate `Ajv2020` class and a second set of options for no feature this protocol uses. Cost: the previous draft schema (2020-12) and its byte copies in flmnt and Sift change. The schema avoids type arrays and `if/then` on the request path so Ajv strict mode and the Rust `jsonschema` crate accept it unchanged.
7. **One spec host per spec file.** The file's response role and every service role share one host process. The adapter keeps a module-scoped registry of open hosts keyed by the host configuration (command, cwd, env). The first role to set up spawns the host; later roles join it; the last role to tear down ends it (close stdin, kill after a grace period). A role with a different host configuration than the open host is refused (`HOST_CONFIG_MISMATCH`). If the host process exits, every call of every role of that file fails with `HOST_CRASHED` and the registry entry is dropped; other files have their own hosts and are unaffected. Scenarios in a host never overlap (vitest runs a file's tests in order), so the host keeps one session and needs no concurrency control.
8. **Where the instrument stops.** This adapter observes through `peekCapture`/`stopCapture`/`read`. At the integration tier the host only invokes; observation goes through product adapters; the Feat Host Protocol is not used by journeys.

9. **Isolation is asserted.** (Ruled.) The runner asserts that vitest runs with module isolation on (the default `isolate: true`) and fails the run before any spec starts if it is off, because the host registry's per-file scope depends on it.
10. **A Feature-owned conformance suite.** (Ruled.) Feature generates a protocol conformance suite from `schemas/feat-host-protocol.schema.json` (every method's valid and invalid requests, every closed result, the null-id parse-error answer, additive setup, `settle` and `peekCapture` semantics, `setClock` freeze and unfreeze, `fault` consumption and disarm on `reset`). Sift's CI runs it against `sift-feat-host`. The fake host of SPEC-RPC-001/002 tests the adapter, never the real host.
11. **Error codes.** (Ruled.) The ADR enumerates -32700 (parse error), -32600 (invalid request), -32601 (method not found), -32602 (invalid params) and -32002 (not set up). The rest of -32000..-32099 stays open to the host.

12. **The runner namespace (ruling 18b625af, "keep it").** One namespace per spec file, derived by the runner (SPEC-RT-006), is delivered to the host in `setup` (authoritative) and in the host's environment as `FEAT_NAMESPACE` at spawn (convenience). The host applies it to every key, stream, topic, label, alias or tag it writes and echoes it in the setup result. Layering: SPEC-RT-006 owns the codes. The transport (SPEC-RPC-001) owns shape: a setup request without a valid namespace is `INVALID_REQUEST` and never leaves the client; a setup answer without the echo, or with a malformed one, is `PROTOCOL_VIOLATION`. A well-formed echo of another value is a valid exchange, and the adapter (SPEC-RPC-002), which compared it with what it sent, fails the file with `NAMESPACE_NOT_HONOURED` before any case runs and ends the host. The namespace is not part of the host registry key (command, cwd, env). Protocol version (ruling a59656b7): the setup request carries `protocol: 2` (integer const) and the setup result carries `protocol` (any positive integer, so that a mismatch is a named failure and not a malformed line). The unversioned wire protocol is version 1; nothing shipped under either. Matching is EXACT: a host speaks one version, a host does not answer a lower version it also supports, and the adapter accepts only 2. Layering, same as the namespace: a request without `protocol: 2` is `INVALID_REQUEST` (never leaves the client); a result without `protocol` is `PROTOCOL_VIOLATION`; a well-formed result naming another version is a valid exchange and the adapter fails the file with `PROTOCOL_MISMATCH` before any case runs and ends the host. The namespace pattern is tightened to exactly `^s[0-9a-f]{12}$` (SPEC-RT-006's derivation) on the request and the echo; a missing echo is `PROTOCOL_VIOLATION` at the transport and `NAMESPACE_NOT_HONOURED` is only for a well-formed echo of another value (ruling a59656b7; SPEC-RT-006's "or none" is being narrowed by another agent). The schema carries no version note; the version lives in the field.

## Consequences

- Every file pays one process spawn and one setup; a file with one response role and N service roles pays one spawn, not N+1.
- A crash is contained to the file that owned the host; the failure names `HOST_CRASHED` on every role, so the report is not a cascade of timeouts.
- Early convergence exit (settle, then peek) works against a real concurrent host, and is never wrong in the optimistic direction: not vouching only costs time.
- The registry depends on vitest isolating module state per file (default `isolate: true`). A run configured with `--no-isolate` would make files share a registry and therefore a host. The runner must keep isolation on; the sharing spec cannot detect a violation from inside one file.
- The clock reaches the host only if the harness calls the optional `setClock` the adapter-interface draft defines (`drafts/adapter-interface/DESIGN.md` section c). Both adapter roles implement it, so a file with only a response role still delivers the clock.
- Every host-written name carries the namespace, so a host that ignores it would make absences (`records []`) pass while the system misbehaves; the echo makes that a refusal instead of a silent pass. The conformance suite (decision 10) adds cases: setup with and without namespace, a malformed namespace, the echo, a second role with another value, and `reset` leaving the namespace unchanged.
- The Sift host must change; the work is listed under "Sift-side work" below.

## Rejected alternatives

- **One host per adapter role.** Simple, and independent crashes. Rejected: a response role and N service roles would each hold a separate process with separate state, so a record the response role's invoke writes could not be seen by a service role's capture; the host's ports ARE the shared world. It also multiplies spawn cost by N+1 and gives no single owner for the clock.
- **One host per run.** Cheapest. Rejected: files run in parallel workers, so every file's scenarios would interleave in one session; reset, seed and capture windows are per-scenario and would collide. It also makes any crash a run-wide failure and forces a cross-process registry.
- **A multiplexed host with session ids.** One process, many concurrent sessions, each carrying `session` on every call. Rejected for now: it moves isolation into the host (every host re-implements session tables, per-session clocks and faults), adds a field to every method, and buys back only the spawn cost per file. Revisit if spawn cost measures as dominant; adding `session` later changes every closed params shape, so it would be a protocol version change.
- **Keep draft 2020-12 and byte parity with flmnt/Sift.** Rejected in decision 6; ruled agreed (draft-07); the rename reaches the copies in flmnt and Sift either way.

## Sift-side work: the ten divergences of `sift-feat-host`, plus the namespace and the protocol version

All in `sift/crates/sift-feat-host/src/`. Listed for the Sift workspace to schedule; none edited here.

1. `host.rs:81-82`: an unparseable line, or one without an id >= 1, gets no reply. Required: answer with `id: null` and -32700 or -32600.
2. `host.rs:92`, `host.rs:95-97`: `setup` replaces the whole session and `teardown` drops it. Required: additive, per role, per named service.
3. `host.rs:115-125`: the clock is read from `setup` (default `Utc::now()`). Required: `setup` has no clock; the clock arrives by `setClock`.
4. `host.rs:142-145`: `reset` neither takes nor clears a clock. Required: `reset {}` clears state, windows and armed faults; a new method `setClock {clock | null}` sets or unfreezes the clock.
5. `host.rs:137-138`, `ports.rs:31`: seed records are accepted as opaque values. Required: `SeedRecord` (`type`, `schemaName?`, `values`).
6. `host.rs:150`, `ports.rs:56`, `ports.rs:35`: capture results are whatever the handler recorded. Required: `CapturedRecord` (`type`, `key?`, `payload`, numeric `timestamp`, `metadata?`).
7. `ports.rs:62-66`: a non-object read query matches everything. Required: the query is an object (the schema refuses anything else); the top-level subset equality at `ports.rs:61-69` stays.
8. `host.rs:146-149`, `ports.rs:51`: `startCapture` ignores `specType`. Required: accept it and keep it for the window.
9. `host.rs:158`: `peekCapture`, `settle`, `fault` (and `deliver`) fall through to a -32601 whose message names `deliver`. Required: implement `peekCapture` (non-destructive), `settle` (vouch only after every spawned task finished; false otherwise) and `fault` (armed per scenario, consumed at the port, disarmed by `reset`); `deliver` per its own spec; the -32601 message names the method actually refused.
10. `host.rs:11`, `host.rs:23`: the schema is embedded from `contracts/adrs/feat-wire.schema.json` as draft 2020-12 and handlers are synchronous (`Handler = fn(...)`). Required: embed `feat-host-protocol.schema.json` (draft-07), validate results against `#/definitions/results/<method>` before sending, and track spawned tasks so `settle` is honest once handlers spawn.
11. (New, ruling 18b625af) `setup` takes `namespace` and the host keeps the first value, answers -32602 to a later role naming another, applies the prefix to everything it writes in the product forms of `drafts/product-adapters` (`<ns>.` stream and topic prefix, `<ns>#` partition-key prefix, `ns_<ns>` node label, `feat:namespace` tag or `alias/<ns>/`), echoes it in the setup result, and reads `FEAT_NAMESPACE` only as a fallback. Today `host.rs:91-93` and `setup` at `host.rs:107-126` know no namespace, and `Port` (`ports.rs`) keeps unprefixed records.
12. (New, ruling a59656b7) `setup` takes `protocol` (the host answers `protocol: 2` in its setup result and refuses, with -32602, a request naming another version) and its namespace echo matches `^s[0-9a-f]{12}$`.
